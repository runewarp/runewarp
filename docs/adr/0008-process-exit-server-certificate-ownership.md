# Process-exit Server certificate ownership

Server ACME uses one stable local process-held file lock and retries interrupted CA work after actual owner exit. We accept abandoned or repeated orders instead of adding dependency quiesce controls or transferring renewal state. Retaining the lock descriptor until process exit prevents cancelled futures, detached cache I/O or a dropped runtime from handing ownership to another process while local work can still run. This requires a sequential migration from nonparticipating binaries, cooperative use of one local lock inode, immutable durable serving exports, and fresh consumed challenge-route evidence before a new owner drives ACME. Ordinary TLS remains on an independently validated snapshot until a durable usable active candidate replaces it; finite recovery ends in maintenance before certificate safety is exhausted.
