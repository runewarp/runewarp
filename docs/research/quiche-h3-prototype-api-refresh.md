# PROTOTYPE: quiche HTTP/3 API refresh

Research support for the published-quiche-first prototype informing [#239](https://github.com/runewarp/runewarp/issues/239), current on 13 August 2026. This is implementation evidence, not a production stack selection or an evergreen runtime contract.

## Version baseline

Use published `quiche` **0.29.3**, released 14 July 2026. It remains the newest registry release and resolves to tagged source commit `55886df3be579579207104c8e645825b6347a209`. The crate requires Rust 1.88 and enables its `boringssl-boring-crate` integration by default. [0.29.3 release](https://github.com/cloudflare/quiche/releases/tag/0.29.3) [registry entry](https://crates.io/crates/quiche/0.29.3) [tagged manifest](https://github.com/cloudflare/quiche/blob/0.29.3/quiche/Cargo.toml)

## Production-shaped implications

Published quiche can attempt every wire behavior in the matrix without a dependency patch. “Can attempt” is not “already implemented”: exact GOAWAY rejection, Runewarp request semantics, malformed-message mapping, H3 Datagram framing/routing, Context IDs, lifecycle Capsule framing, identity authorization, and terminal task ownership all remain adapter code and require real-network fixtures.

The Public QUIC carrier is the weakest ergonomic area. quiche exposes negotiation plus raw QUIC DATAGRAM transport, not an H3 request-associated Datagram API. The prototype should therefore count the manual Quarter Stream ID/Context ID codec, request-liveness table, malformed-datagram handling, and Capsule parser as Runewarp-owned integration burden. That is a truthful published-library result, not grounds to patch quiche before measurement.

The TLS/runtime migration is material. Runewarp must replace Quinn endpoint/connection lifecycle and rustls identity plumbing with a manually driven quiche connection and BoringSSL configuration. quiche and its TLS backend contain dependency-internal `unsafe`/FFI; the Runewarp adapter must introduce no `unsafe`.

## Focused proof gates

1. A certificate-less Client fails the TLS handshake; a trusted certificate connects; `peer_cert()` yields the expected verified leaf identity.
2. Both peers advertise two arbitrary Runewarp SETTINGS, observe the raw peer pairs, and fail closed for absent/invalid mandatory signaling.
3. Server sends first-unprocessed GOAWAY ID `4n`; Client observes exactly `4n`; streams below it finish and streams at/above it are explicitly cancelled and never committed.
4. Read and write shutdown fixtures observe caller-selected H3 codes in the peer events.
5. Resumption succeeds without either endpoint entering application early data or exposing H3 state before establishment.
6. One Extended CONNECT request carries bounded lifecycle Capsules reliably and separately carries H3 Datagrams framed as Quarter Stream ID, Context ID, and a real 1200-byte inner Initial in both directions when the measured ceiling permits.
7. Repeated normal and error teardown reaches `is_closed()`, drains all connection output/timers, terminates the sole owner task, and leaves ordinary signaling independent of carrier cleanup.
