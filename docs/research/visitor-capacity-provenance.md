# Visitor benchmark source provenance

The benchmark runner verifies the executable before launching measured roles. It hashes the relative names and contents of Cargo.toml, Cargo.lock and Rust files under src, passes the fingerprint through a compiler-tracked environment variable, then requests that fingerprint from the ignored test binary's provenance role. It rejects a mismatch or a binary without that role. It also rejects source changes during the build. This catches stale shared-target artifacts from archived sources whose mtimes or surrounding Git ignore rules do not force a rebuild.

After building, the runner copies the executable into its private output directory and launches every role from that fixed copy. A later Cargo build cannot replace a role executable during the capture. Environment metadata records the verified Rust-source fingerprint, binary SHA-256, source revision, tracked dirty state and product-diff SHA-256. Script/output/executable locations are omitted. Preflight provenance checking is part of build preparation, before measured role processes and the scenario cooldown.

For archived controls, use a separate CARGO_TARGET_DIR and disclose the archive commit plus any harness-only overlay. Old harness revisions need the current test-only provenance role to work with the current coordinator; label that overlay explicitly. A source-revision override identifies the exported Rust source, not the surrounding checkout's HEAD. Record the surrounding HEAD and coordinator version separately when they differ. An override cannot make a stale binary pass the compiled-source check.

The reference measurements preserve the earlier stale-binary diagnostic, corrected by matching its executable hash to the original-head control. That failure is not presented as fixed-source evidence. Raw build/provenance logs and copied executables remain private under target. The public record retains portable metadata, measurements and failure counts.
