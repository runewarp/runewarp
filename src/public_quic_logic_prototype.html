Can the relay lifecycle stay coherent?

This demo tests one provisional model: the Server allocates a never-reused Context ID, reliable Capsules register and close it, and unreliable H3 Datagrams carry one opaque Visitor QUIC packet each. Push it through reordering, rebinding, drain, isolation, and Tunnel loss to find where the ownership model feels wrong.

This is a state-model experiment, not network proof. It assumes classification already produced an authorized Public hostname. It cannot validate Initial parsing, ECH, real MTU, packet loss, nested congestion, Rust H3 APIs, or backend HTTP/3 behavior.

Inputs retained from current issue evidence: one existing authenticated H3 connection; H3 Datagrams for packets; reliable Capsules for lifecycle; Server-allocated, carrier-local Context IDs; no reliable packet fallback; no cross-Tunnel continuity. Assumptions to challenge here: capability gates carrier opening, one carrier is enough, two early packets may be buffered, and an MTU cliff stops new admission. Those activation, count, limit, and withdrawal policies remain provisional.
